30 秒结论

闭环成功，候选没有被错误地“包装成成功”

V1 已覆盖真实 Feedback、Creator、Assistant replay、确定性 Gate 与 byte-exact rollback。结果说明系统具备学习信号，也说明风险控制实际生效。

可信结论 新 S1 候选在 replay200 上把 GCS macro 从 21.77% 提高到 25.27%，micro 从 26% 提高到 31%；但视觉百科从 3/40 成功降为 1/40，越过预先冻结的 −3pp 单能力底线。系统因此拒绝整 Bank 候选，并把发布 Bank 按字节恢复为 Static。
机制已验证

真实模型与真实工具

Qwen Feedback 48/48 parsed；Codex Creator 生成六能力候选；replay200 完成 200/200，667 次调用全部结算且无执行错误。

效果未接受

总体改善不等于安全改善

Exact Match 获得显著提升，但视觉百科负迁移。V1 的最终状态是 rolled back，不能声称 S1 已部署或已成为新基线。

面试价值

安全回滚是正面成果

项目展示的不是“每轮必涨分”，而是可归因的候选生成、预注册风险底线、失败即停止，以及不改写历史的回滚能力。

Evidence boundary

一个报告，两条不能混写的证据轨道

两组实验回答不同问题，使用不同 Bank 世代、样本与指标。它们共同组成 V1 证据，但不能合并成一个“总提升”。

Why the result is not ideal

为什么结果不够理想

下列内容刻意区分“产物直接证明的事实”和“需要下一轮验证的推断”。

已验证事实

增益高度集中，而不是六能力普遍改善

整体净增 10 条成功，Exact 一项就净增 10 条；Multi 和 Recipe 各 +1，百科 −2，Style/Document 不变。4/6 capability 没有正增益或出现退化。

已验证事实

合同与路由改善，同时出现新格式回归

route_unacceptable 29→19、tool_contract_failed 29→20、card_contract_failed 39→28；但 output_section_invalid 5→10、fallback_contract_failed 5→7。

已验证事实

部分能力受工具和 evidence ceiling 限制

Document 在 Static 与候选中都是 0/8；Style 也是零增益。只重写 Skill 文本无法凭空创造缺失的证据召回、候选或可靠 DTO。

已验证事实

统计精度仍有限

replay macro CI95 为 [+0.19, +6.67]pp，但只有 8 个 batch component，并带有 low-component-count precision warning；Document 仅 n=8。dev_mini 的主要 CI 则全部跨 0。

待验证推断

Whole-bank rewrite 可能造成负迁移

Creator 同时重写六个 Skill，可能过度吸收 Exact 与高频合同模式，并破坏百科中原本稀少但有效的回答策略。当前 replay 能证明“发生了负迁移”，不能单独证明其内部因果机制。

待验证推断

均衡选样不等于总体分布

Feedback 固定为每能力 6 个 failure + 2 个 anchor，适合故障发现，却不是线上或 replay 的自然频率。Creator 可能对被刻意放大的失败类型赋予了过高权重。

这不是“把 −5pp 安全线放宽一点就能成功” Gate 在候选生成前已经冻结。若根据结果降低门槛、事后拼接五个表现较好的 Skill，或重新解释同一 replay200，都会破坏比较公平性。

Improvement plan

改进建议：先隔离改动，再扩大评测

下一轮算法工作属于 V2。V1 先以本报告、结果表、案例和复现证据完成交付，不继续无界追分。

把 S1 从 whole-bank rewrite 改为 capability-local sparse patch

未被目标 failure cluster 支持的 capability 必须 byte-exact 继承父 Bank；候选同时声明目标规则、预期影响与不得改变项。当前 Exact 改写可以成为假设，但不能从已见结果中直接剪贴为新 Bank。

使用新的预注册 replay / cross-fit

当前 replay200 已经被观察，不能再用于调新候选并宣称独立验证。下一轮要重新冻结 discovery/replay component，或采用 capability-level cross-fit；Gate 阈值保持不变。

为百科与 Document 优先修 evidence，而不是继续堆 prompt

增加正向 regression anchors、知识检索 miss 时的保守拒答、可引用 evidence DTO 与 tool-ceiling 测试。只有 evidence 可达时，Skill 文本优化才可能转化为 GCS。

第二版用 Static-parent、Description-only S2 做风险敏感路由

当前 S1 已回滚，S2 必须以 Static 为父。先做 Exact↔Style / Exact↔Multi confusion-pair 局部修改，以 corrected − 2.5 × broken、per-cap recall floor 和 hard-error 共同 gate。

S3 只在稳定 Body failure cluster 上做稀疏 TextOpt

冻结 route 与 tool trace，每次只改 1–3 条规则；若 route-correct、tool-success 的同签名失败不足 20 条，则不启动 S3，Full 直接 alias 已接受的 S1+S2。

确定性 Gate 通过后，才启用 Gemini / 人工偏好评测

先用 GCS 排除明显回归；只有候选通过后，才花费视觉 Judge 与人工 SBS 预算评价完整语义质量。这样把昂贵、高方差评价放在真正有希望的候选上。

下一步应该做

  • 冻结并发布 V1 结果、图表、案例和声明边界。
  • 为 V2 单独预注册新数据分配、候选 scope 与预算。
  • 先跑零/低成本 deterministic replay，再决定是否进入 route/body gate。

下一步不应该做

  • 放宽 −3pp floor 或修改 GCS 规则。
  • 从当前候选中事后挑选“赢的能力”直接发布。
  • 在已经看过的 replay200 上调参并重复宣称独立验证。
  • replay 失败后继续访问 body_gate、val 或 test。

Claim boundary

局限与可声明范围

这是一项面向求职展示的 Portfolio 工程实验，不是企业线上 A/B，也不是论文绝对分数复现。

可以声明

  • 五配置、六 capability 的真实模型与工具矩阵已运行。
  • failure-driven Feedback → Creator → replay → rollback 闭环已真实执行。
  • 候选产生总体正向信号，Exact 改善明显，但因能力级负迁移未被接受。
  • 调用、usage、可计成本与回滚 Bank hash 有可复核产物。

不能声明

  • S1 已成为新的生产 Bank 或系统已整体提升。
  • 五配置方向性差异已经统计显著。
  • GCS 等同完整语义质量或人类偏好。
  • 结果代表企业生产流量、私有工具或论文原始数据。
  • 未运行的 body_gate、val、test 或 Gemini Judge 已通过。
样本

低 component 精度

replay 只有 8 个 batch component；Document n=8，能力点估计不稳定。

指标

J 与 GCS 不可混用

dev_mini 使用历史 J_project；新 S1 使用 GCS v2。两者不能拼成统一效应量。

评价

尚无人类最终偏好

新 S1 在前置 GCS gate 即失败，Gemini 与人工 SBS 均未启动。
