## 5. ManualSkill 决定

用户不具备各电商 capability 的领域专家知识，这不是主比较的阻断项，也不应通过用户手写或 LLM 代写后冒名为论文 `ManualSkill` 来解决。

主实验固定采用：

- `LLMStaticSkill` 作为主静态基线：与 S1 共享作者模型、AuthoringPacket、公开资料、Reference Skill（若使用）和 authoring budget，但不能读取任何轨迹、评价反馈或结果。
- `SpecBaseline` 作为不调用 LLM 的诊断下界，不进入五配置主表。
- 结果中明确写明论文的 expert ManualSkill 未复现，因此不能回答“自动方法是否优于人类专家基线”。主问题改为回答 S1 是否优于同模型、同预算且不读取轨迹的一次性静态 authoring。

未来如果确有必要补充专家列，可招募未接触项目轨迹和结果的独立合格专家。专家只填写结构化领域表单，不需要编写 SKILL.md；项目的确定性编译器负责转换。资格、可见资料、固定工时/报酬、无结果访问声明、人工 diff 和最终 hash 必须留档。若内容阶段使用生成式 AI，则只能命名为 `ExpertCuratedLLMSkill`，不能命名为 ManualSkill。
