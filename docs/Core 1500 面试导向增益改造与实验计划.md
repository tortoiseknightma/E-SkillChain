# Core 1500 面试导向增益改造与实验计划

## 1. 结论与目标

200×5 已证明执行链基本稳定，但现有质量增益被评测噪声和全 Bank 统一优化抵消：

| 配置 | Mean J | Route macro-F1 | 合同成功率 |
|---|---:|---:|---:|
| NoSkill | 69.29 | N/A | — |
| LLMStatic | 70.37 | 0.814 | 77.5% |
| S1 | 71.75 | 0.839 | 81.0% |
| S1+S2 | 72.23 | 0.922 | 88.5% |
| Full | 71.56 | 0.922 | 与 S1+S2 同 Bank |

- Static→S1+S2 的 J 仅 `+1.86`，置信区间跨零；但路由和合同成功率提升显著。
- 相同 Bank 的 S1+S2/Full，逐题 J 差值 `MAE=12.93、SD=18.57`，说明单次绝对 Judge 噪声远大于当前算法增益。
- S1+S2 相对 Static 的 J 增益集中在 Multi `+13.31`、Document `+4.92`；Exact、Encyclopedia、Recipe 均退化。按 core test 分布机械重加权，预期总增益只约 `+0.72`。
- 简单文本分类器在 core test 已达约 `0.955 macro-F1`，图片来源前缀基线约 `0.965`；旧 200 运行还向模型暴露了 `image_path`。总体路由高分不能单独作为能力主张。

最终面试主张设为：

> 通过失败驱动的 Skill Creator、混合 Route Optimizer 和 evidence-aware Refiner，把路由改善转化为可复核的任务成功率、语义偏好、成本和可靠性收益。

## 2. 核心改造

### 数据与运行时

- 保留 formal `core-final-evaluation-framework-v1`，新增 Portfolio-oriented v2 契约；不修改历史冻结文件。
- 固定使用现有 `dev200 / opt800 / val200 / test300`：
  - dev：仅诊断；
  - opt：失败采集、训练和候选生成；
  - val：唯一接受/回滚依据；
  - test：一次性解封，禁止调参。
- core 启动时禁止 `--legacy-launch-compat`，断言模型可见输入只能包含 opaque `asset_id/text/turns`；任何路径、数据源、模板或 canonical label 出现均直接阻止运行。
- 增加 text-only 和 source-only shortcut baseline，分别报告 overall、boundary、cross-intent，不包装成多模态能力。
- 新建独立 `interview_challenge=120`，不修改 test300、不参与训练或 gate：
  - 六能力各20条；
  - 10组 Exact/Style/Encyclopedia 三元组；
  - 10组 Exact/Multi、10组 Document/Encyclopedia、10组 Recipe/Multi；
  - Style、Document、Recipe 各10条无显式意图词 hard single；
  - 75% 为同图跨意图，60条单轮、60条三轮，至少30条包含否定或末轮目标切换；
  - 禁止直接标签词和路径信息，按资产组整体冻结。
- 只有 `public_demo_allowed` 的资产可进入最终面试案例。

### Evidence contract 与回答生成

- 为 `StyleHit` 增加可选 `StyleFacetEvidenceV1`：facet、value、confidence、provenance。优先使用公开元数据/FashionIQ 相对描述，缺失时使用一次性视觉抽取并明确标记为模型预测。
- 将 Multi 可见证据统一为 `VisibleMultiItemV2`：`item_ref / label / bbox / grounded_hit|null`，保留逐物体关联、去重和未命中状态。
- 新增 `SemanticAnswerSlotsV1`。Full 配置下由 LLM 只生成简短语义槽位，代码负责 cards、evidence reference、item mapping 和固定章节：
  - Style 最多3个候选、每个最多2个有证据 facet；
  - Multi 对每个 item 明确命中或 unresolved；
  - 不允许正文引用不可见字段。
- 所有配置共享相同工具证据；结构化 composer 是 Full/S3 的明确算法组件，作为五配置消融的一部分披露。

### S1/S2/S3

- S1 改为逐 capability 的坐标优化：
  - opt800 按 capability × failure signature 生成 `FailureClusterV1`；
  - 每类最多生成 grounding、completeness、conciseness 三个稀疏 patch；
  - 每次只改一个 section，Body 长度变化不超过20%；
  - 独立通过 val gate 的 capability patch 才组合为新 Bank，退化能力保留 Static 版本。
- S2 使用混合路由：
  - 本地模型固定为字符 2–5 gram TF-IDF + balanced Logistic Regression；
  - 只读取用户 turns，不读取 asset/path/source/template；
  - 在 opt800 训练，并加入 cue-dropout、同图跨意图和 confusion-pair hard negatives；
  - 高置信预测直接路由，低置信或 top-2 margin 不足时回退视觉 LLM；
  - 阈值在 val 上选择：先最大化 macro-F1，0.5pp 内选择 LLM fallback 更少者；每类 recall 不得下降超过5pp，cross-intent 不得低于纯 LLM。
- 将 `SharedStage2RouteArtifact` 升级为向后兼容的判别式 provenance：
  - 记录 `backend=local_classifier|vision_llm`、模型/训练集哈希、top-k 概率、阈值、margin、reason code 和 fallback reason；
  - 本地路由 usage 为真实零值，LLM fallback 才带 `model_call`；禁止伪造调用 receipt。
- S3 只生成 targeted section patch，不再整段重写 Body；可修改 success rule、tool step、fallback 或启用 capability-specific composer。Structural adherence 仅作 hard guard，不能单独推动接受。
- 收敛当前两套 gate 语义，以 Portfolio v2 gate 为唯一执行入口；历史通用 gate 保留兼容读取但不参与 core 决策。
- 最多三轮有记录的算法迭代，三轮后无论结果如何停止。

## 3. Gate、执行和评测

### Val gate

- S1/S3 affected-capability：
  - Contract Success 至少 `+5pp`；
  - 自动 pairwise tie-adjusted preference 不低于 `0.50`；
  - hard error、card/evidence violation不得增加。
- Document val 仅10条：只有至少2条净改善且其余全部非退化时才接受，否则保持 Static，并标为 exploratory。
- S2：
  - route macro-F1 至少 `+3pp`；
  - 每类 recall 下降不超过5pp；
  - boundary/cross-intent 非退化；
  - 至少20个 route flip；
  - flip rows 做两次 parent/candidate rollout，Contract Success 与 pairwise 价值均非负。
- 组合 Bank 再做全局交互 gate：capability-macro Contract Success 至少 `+2pp`、cluster-bootstrap 下界不低于0、hard error 非劣不超过1pp。
- 未通过即回滚。若 S3 回滚，`Full` 明示为 `S3 rollback control`；分析器按 Bank/算法哈希识别 no-op，不声明 Full 增益。

### Core 执行

- 1500 条全部跑廉价 route-only，Static、S1、Hybrid 分 split 报告；all1500 只作描述性统计。
- val200 对最终五配置各跑两次，用于消融和冻结最终 Bank。
- test300 在一次解封事件中运行五配置×两次，共3000 Assistant rows；两次使用预冻结 run-id/seed 表，按 query 先求均值，不能把重复视为独立样本。
- challenge120 对 Static 和 Final-Evolved 各跑两次。
- 沿用现有25-query shard/coordinator；并发 canary 通过后冻结 `Qwen inflight=2 / Kimi inflight=8`，否则冻结为 `2/4`，正式运行中不按中间分数调整。
- Primary：
  `Capability-macro E2E Contract Success = acceptable route + no hard error + required tool success + card/evidence contract`。
- Secondary：route macro-F1/accuracy/per-class recall、boundary/challenge 表现、hard errors、card/evidence compliance、fallback rate、token、成本和延迟。
- 统计统一按 leakage group 做10k cluster bootstrap；route accuracy 同时做配对 McNemar。

### 语义质量

- Pairwise Judge：
  - dev60对做左右交换校准，共120 calls；
  - 交换一致率≥85%、weighted agreement≥0.75、解析失败率<1% 才能成为正式 secondary；
  - test Static vs Final 两次重复共600对；challenge做120对。
- 人工盲评：
  - test 预冻结100个 query：Exact25、Multi15、Style20、Encyclopedia20、Document8、Recipe12，至少20个 boundary；
  - 插入20个隐藏重复项检查自身一致性；
  - 本地盲化 reviewer 只显示图片、对话和随机左右响应，映射单独保存。
- 为和 200 结果接轨，在同一100个 test 样本的一次预指定重复上，对五配置计算 legacy `J_project`；只作为兼容性指标，不作为成败门。

## 4. 验证与成功标准

聚焦测试必须覆盖：

- opaque input 无路径/来源泄漏；
- 本地/LLM 两种 route provenance、零 usage 和 shared reuse；
- classifier bundle、训练 split、阈值与输入哈希可复现；
- Style facet provenance 与 Multi item/card 一一对应；
- composer 无法生成 evidence 中不存在的字段；
- capability patch 组合、gate、rollback 和同 Bank no-op 识别；
- 外部冻结 shard 的多 root 分析，修复当前全200报告不能一次生成的问题；
- 两次重复、cluster bootstrap、Judge 左右交换和人工盲化映射；
- 25-query smoke 的恢复、全局 circuit breaker 和无重复调用。

最终可讲“整体系统增益”必须同时满足：

- test300 Final-Evolved 相对 LLMStatic：
  - capability-macro Contract Success `≥+5pp` 且95% CI下界>0；
  - route macro-F1 `≥+3pp`，McNemar `p<0.05`；
  - hard error 非劣不超过1pp；
  - 人工 tie-adjusted preference `≥0.55`；CI下界>0.5 时才称稳健质量提升。
- Hybrid 本地覆盖率≥70%，route 阶段 LLM 调用减少≥70%。
- challenge route macro-F1≥0.80 且相对 Static≥+5pp。
- 若只满足 routing/cost，不声称整体质量提升；若三轮后仍未达到质量门，交付真实负结果及根因。

## 5. 预算、假设与交付

- 当前 200×5 约 CNY133.85，约99%来自 Kimi Judge；直接7500次绝对 Judge 预计约 CNY1000，因此不执行1500×5。
- core 建议新建独立阶段预算：目标增量 CNY180、硬上限 CNY200；当前 dev 阶段累计 cap 不自动视为 core 授权。
- Pairwise 校准的前40 calls 同时作为成本 smoke。若均价> CNY0.10 或预测超过目标：
  - test pairwise 降为预指定单次重复300对；
  - legacy J 降为50个样本×五配置；
  - human100与确定性 primary 保持不变。
- 若 Pairwise 校准失败，自动 Judge 降为 exploratory，只保留300对测试；人工与确定性指标承担正式结论。
- 最终交付五配置 val/test 表、shortcut/challenge 表、路由与成本图、闭环架构图、2–3个机制案例、失败限制、可复现命令，以及30秒/2分钟面试介绍。
