### 0.3 ManualSkill 的替代决定

用户不具备电商各 capability 的领域专家知识，因此不能诚实地把自己手写的 Skill 称为论文中的专家 `ManualSkill`。主实验采用以下替代：

- **LLMStaticSkill（主基线）：** 与 S1 使用同一作者模型、Task Specification、ToolSpec、允许的公开资料、固定模板、预注册 authoring budget，以及若使用则双方共享的 Reference Skill，但只能一次性生成，不能读取任何项目轨迹或评测反馈。
- **确定性收口：** 作者模型输出严格结构化 draft，版本化编译器再按固定顺序生成 Description、Body、Cs、Od；保存完整 prompt、raw output、模型身份、tokens、费用、人工 diff 和所有输入输出 hash。
- **严格信息边界：** LLMStaticSkill 不得读取任何 pilot/opt/val/test 轨迹、标签、Assistant 响应、S1/S2/S3 Bank、rubric/gold、Judge 输出或指标。
- **用户职责：** 用户只检查 schema、工具权限、公开来源引用和安全 checklist，不负责凭空创造领域规则。任何实质性人工内容修改都必须记录，不能重新标成纯 ManualSkill。
- **公平比较：** LLMStaticSkill 与 S1 共享完整 AuthoringPacket 和用户审查分钟上限；S1 唯一额外信息必须是预注册的 TrajectoryBundle。若 Reference Skill、示例或其他 authoring 信息只提供给一方，RQ1b 必须降级为复合 pipeline 比较。模型 tokens、机器时长和人工分钟分项报告。
- **诊断下界：** 另生成不调用 LLM、直接从 Task Specification 编译的 `SpecBaseline`，用于区分“仅注入规范”和“一次性 LLM authoring”的增益，不进入五个主配置。
- **命名边界：** 结果中始终使用真实名称。只有以后获得未接触项目轨迹/结果的合格独立领域专家时，才增加可选 `ExternalExpertManual` 补充列。

可选 `ExternalExpertManual` 不要求专家理解 SKILL.md。项目提供结构化表单，让专家只填写 capability 范围、工具触发与顺序、回答步骤、输出约束、事实来源、拒答和 fallback，再由确定性编译器转成 Skill。专家资格、固定工时/报酬、可见资料、无项目结果访问声明和最终 hash 必须留档；若内容阶段使用了生成式 AI，则改标为 `ExpertCuratedLLMSkill`，不能再称 Manual。

因此五个主配置改为：

```text
NoSkill / LLMStaticSkill / S1 / S1+S2 / Full
```

这个替代不会复现论文的专家人工基线，但能更干净地回答：**从轨迹学习得到的 S1，是否优于相同模型与 authoring budget 下、不使用轨迹的一次性静态 Skill。** 该差异必须写入 Reproduction Contract 和最终局限。

## 1. 执行顺序与并行关系

| 工作流 | 前置依赖 | 可并行项 | 阻断下游的验收门 |
|---|---|---|---|
| A. C1 Codex v4 候选冻结、审批与正式 authoring 调用 | 先在无 inference 条件下生成/复验 exact v4 candidate；owner 再确认双摘要、预算、guard/retirement/approval/claim/output/receipt 路径与证据限制。代码/审计收口本身不授权调用 | 可与 RAW 会话及 B 并行；调用本身不依赖真实 C3 tool runtime receipt | 取得 P0-01 的新调用证据；最终 Bank compile/C1 关闭仍等待 D |
| B. RAW handoff 与逐源审批 | RAW 会话发布 source lock、文件清单和许可证据 | A、C 的资源/候选规则预注册 | 未完成 handoff/审批时禁止运行正式 adapter |

| E. C4/C5 Assistant、Judge 与 mini 纵切 | A、C、D 全部通过 | 无 | P0-06、P1-03、P1-04 |

关键路径为：

```text
RAW 会话 ─> handoff contract ─> owner review ledger ─> adapter/catalog
                                                   ├─> Exact Match 裁决
                                                   └─> tool dev gold ─> 模型/index ─> runtime lock/receipt
v4 candidate 冻结 ─> owner exact 确认 ─> guard/retirement/approval ─> 唯一 authoring receipt ─┐
runtime lock/receipt ───────────────────────────┴─> Bank compile
formal tool report + runtime-bound Bank ─> Assistant/盲化评价 ─> 200-query mini
```

任何阶段若只能生成 `provisional` 或 `diagnostic` 产物，可以继续做工程调试，但不得越过对应 formal gate。

RAW 会话的最小 handoff contract 是逐源交付：`source_id`、不可变 `source_revision`、canonical source-lock SHA-256、文件 inventory manifest 及其外部摘要、实际获取位置或只读根、许可证据原始字节及 SHA-256、提取/解包说明、已知 PII/条款风险和缺失项。只给一个可变目录、“latest” URL、下载成功截图或由同一个 builder 自算的摘要，都不能启动 formal adapter。项目所有者的 license/PII/用途决定由本流程另行签署，不由 RAW 会话代签。
